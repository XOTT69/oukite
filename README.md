# OUKITEL Home 3.0

Мобільний PWA для моніторингу й планування автономності OUKITEL P2001E Plus.
Керування AC/USB/DC залишається у Wonderfree. Застосунок не має endpoint-ів
для команд на фізичну станцію; Home Assistant не потрібен.

## Доступність і достовірність

- Онлайн/офлайн показуються лише за розпізнаним статусом хмари.
- Відсутній або незрозумілий статус означає **«Статус невідомий»**, а не офлайн.
  Навіть тоді застосунок запитує телеметрію, але не видає кешовані показники
  за підтверджене живе вимірювання.
- «Отримано» — час читання хмари. «Виміряно» — окремий timestamp,
  якщо хмара його передала. Відповідь HTTP 200 не доводить фізичний онлайн.
- Завершена сесія, помилка хмари, застарілі показники й телефон без інтернету
  мають окремі стани. LIVE-режим ніколи не використовує демо-значення.
- Останній реальний знімок та історія ізольовані за акаунтом і станцією.
  Стара неізольована історія v2 залишається в localStorage, але не використовується
  для навчання: її належність конкретній станції не доведена.
- Відсутні поля телеметрії залишаються невідомими, не перетворюються на 0 або OFF.

## Прогноз і плани

Енергія до резерву: `2048 × max(0, SOC − резерв) / 100 × 0,88` Вт·год.
Резерв — абсолютний недоторканний рівень заряду, а не частка залишку.
Коефіцієнт 0,88 — приблизний запас на втрати, не калібрування ефективності станції.
Прогноз передбачає відсутність подальшого заряджання.

- Головний екран: автономність за фактичним середнім останніх 24 год,
  або за поточним виходом, поки даних мало; джерело оцінки вказане.
- «План»: незалежний сценарій «що буде, якщо» — зміна приладів завжди
  змінює саме сценарний результат.
- Середнє споживання інтегрується за часом; паузи холодильника враховуються.
  Пропуски понад 12 хвилин не заповнюються вигаданими значеннями.
- Діапазон прогнозу — обмежена сценарна оцінка за годинними середніми,
  не статистичний довірчий інтервал і не гарантія.
- Вимірювання одного приладу: лише дані після початку його сесії, мінімум
  6 год реального покриття. Інші прилади потрібно від’єднати самостійно.
  Станція бачить загальне навантаження і не розділяє його за приладами.
- Редагування приладів, активні/неактивні навантаження, введення відомого
  середнього, чотири шаблони та до 12 власних сценаріїв.

## Фоновий збір і історія

Збір вмикається окремо в налаштуваннях. Worker опитує станцію раз на 5 хвилин,
навіть при закритій PWA. Сама станція повинна мати інтернет. За завершення vendor
token потрібен повторний вхід; пароль для автоматичного входу не зберігається.

Якщо онлайн-статус і timestamp вимірювання обидва невідомі, сервер призупиняє
збір, щоб не навчатися на непідтверджених кешованих показниках.
П’ятихвилинні точки можуть пропускати короткі цикли — Wh є оцінкою,
а не показником окремого лічильника.

Нові записи зберігаються до 31 дня; старі v2-записи мають попередній 14-денний TTL.
Є періоди 1/6/24 год, 7/30 днів, графік із часовою віссю та розривами,
добові підсумки з покриттям даних, журнал портів, JSON-експорт планів і CSV історії.
Імпорт планів не змішує чужу історію з поточним прогнозом.

Зупинка моніторингу й logout видаляють службовий token, але не стирають історію.
Окрема дія очищає історію: нова генерація робить попередні записи недоступними,
а фізично вони видаляються за TTL/cleanup. Cron не продовжує собі 31-денний lease;
його продовжують лише явне налаштування або авторизований повторний вхід.
KV має eventual consistency, тому зупинка між регіонами може застосуватися
не миттєво; жодних фізичних команд цей збір не надсилає.

## PWA, дизайн і доступність

Єдина SVG-іконографіка, великі зони натискання, українські одиниці,
збільшений текст, reduced-motion, safe-area та поля 16 px для iPhone.
Масштабування зафіксоване відповідно до запиту користувача.
Статуси портів не виглядають як робочі перемикачі.
Оновлення PWA встановлюється як цілісний набір файлів; API не кешується.
Офлайн-навігація працює і з `?v=2`.
Попередження низького заряду — лише у відкритому застосунку; Web Push не реалізовано.

## Розгортання

1. `npm ci`.
2. `npx wrangler whoami`: потрібен акаунт-власник існуючого Worker,
   не довільний інший Cloudflare-акаунт.
3. KV namespace уже в `wrangler.toml`. Не змінюйте його без міграції.
4. `MONITOR_KEY` — випадковий серверний secret від 24 символів. Наявний
   ключ не перезаписувати: це зламає розшифрування збережених сесій.
5. За потреби підключіть D1 через закоментований блок конфігурації та застосуйте
   **обидві** міграції: `npx wrangler d1 migrations apply oukitel-home --remote`.
   Без DB працює KV fallback із пакетним читанням до 100 ключів, без обрізання
   тижневої історії до 720 точок. Старі KV-записи залишаються доступними при переході.
6. `npm run check`, `npm test`, `npm run test:browser`,
   `npx wrangler deploy --dry-run`.
7. `npm run deploy`. Cron викликається щохвилини, але кожна станція опитується
   не частіше п’яти хвилин. D1 обирає найдавніші спроби, KV має обхід із cursor.
8. Перевірте `/api/health`: version, storage, sessionEncryption.
   Цей endpoint перевіряє наш сервер, **не онлайн станції**.
9. Для реального обладнання — `LIVE_TEST_PROTOCOL.md`.

## Тести та безпека

Юніт-/інтеграційні тести включають справжню локальну D1 з обома міграціями,
атомарний D1 rate-limit, account isolation, lease, шифрування, резерв, цикли,
пакетне читання історії й невідомі поля.
Browser-тести — Chromium та WebKit із штучними cloud-відповідями.
Офлайн-емуляція навігації Playwright WebKit обходить service worker і пропускається:
для цього сценарію обов’язкова перевірка на фізичному iPhone.
Жоден синтетичний тест не замінює live-перевірку вашої станції.

Пароль передається лише через HTTPS для входу. Token залишається на сервері
у 12-годинній HttpOnly/Secure/SameSite cookie-сесії; за наявності MONITOR_KEY
зашифрований AES-GCM. Token моніторингу завжди зашифрований.
Логи не містять vendor-повідомлень чи ідентифікаторів користувача.
Vendor appSecret у коді — параметр публічного мобільного протоколу, не пароль.

Напряму UDP/TCP-протокол станції з iPhone PWA недоступний.
Підтримується лише read-only EU Wonderfree/Quectel Cloud.
