# OUKITEL Home — P2001E Plus

Самостійний PWA для OUKITEL P2001E Plus. Він показує реальні дані з Quectel/Acceleronix Cloud у **read-only** режимі та не віддає Wonderfree password, bearer token або `authKey` браузеру.

## Що працює

- вибір прив'язаної до акаунта станції;
- SOC, час, потужність входу/виходу, AC/DC input, температура, частота, напруга, firmware та зарядний ліміт;
- явний статус «онлайн», «офлайн», «дані застаріли» та ручне оновлення;
- історія 1 / 6 / 24 год та 7 днів із графіком, журналом змін AC/USB/DC;
- опційний фоновий моніторинг: Worker читає телеметрію раз на 5 хвилин навіть коли PWA закритий, зберігаючи вибірку 14 днів;
- адаптивний прогноз автономності за фактичними Wh, а не паспортною потужністю приладу; нульові проміжки в циклі холодильника враховуються;
- план автономності, профілі «Ніч», «Робота», «Блекаут», «Котел», власні прилади, калібрування окремого навантаження та резерв батареї;
- діагностика, великий текст, експорт та імпорт локальних планів і історії;
- PWA/offline shell, без кешування будь-яких API-відповідей;
- server-side сесія Cloudflare KV з `HttpOnly`, `Secure`, `SameSite=Strict` cookie;
- cloud read-only: endpoint-и для write-команд навмисно відсутні.

Інтерфейс фіксує випадкове масштабування на iPhone (maximum-scale=1,
user-scalable=no), але не заважає системним можливостям доступності iOS.

`productKey` для P2001E Plus: `p11wN7`. Це підтверджено в [публічному reverse-engineering проєкті](https://github.com/bordeux/ha-oukitel-powerstation/blob/master/REVERSE_ENGINEERING.md). `deviceKey` вибирається з вашого акаунта після входу — вручну вводити його не потрібно.

## Як користуватися

- **OUKITEL Home:** станція онлайн/офлайн, заряд, споживання, температура, локальна історія та план автономності.
- **Wonderfree:** увімкнення й вимкнення AC, USB та DC.

Це свідомий поділ: рідний застосунок уже має нативний доступ до станції, а цей PWA не імітує небезпечні cloud-команди. На екрані «Виходи» завжди видно останній відомий стан портів і коротку підказку, де його змінити.

## Розумний прогноз і фоновий моніторинг

У налаштуваннях є окремий перемикач **«Фоновий збір фактичного
споживання»**. Після явного увімкнення Worker зберігає зашифрований cloud token
та збирає лише read-only телеметрію раз на 5 хвилин. Це працює, коли PWA
закритий, але лише якщо сама станція має живлення й доступ до інтернету.

За першої години даних застосунок використовує обережний прогноз; за добу він
стає стабільнішим. Для калібрування холодильника натисніть «Виміряти» поруч із
ним у плані та на 6+ годин залиште на станції активним лише холодильник. Якщо
разом працюють інші прилади, Worker бачить тільки їхню сумарну потужність і не
може чесно відокремити холодильник від неї.

Вимкнення моніторингу або вихід із Cloud негайно видаляють службовий запис і
накопичені фонові вибірки. Пароль Wonderfree не зберігається.

## Попередження

Опція низького заряду показує toast і системне повідомлення під час
відкритого застосунку та успішної синхронізації. Фоновий збір даних не означає
фонові push-нагадування: для них все ще потрібні окремі Web Push-підписки й
явний дозвіл користувача.

## Технічне обмеження

Safari PWA не може відкривати UDP `6606` або TCP `6607`, тому напряму до станції у LAN підключитися не здатний. Перевірений локальний протокол потребує окремого bridge-процесу в тій самій мережі (наприклад Raspberry Pi, NAS або домашній сервер); це не вимагає Home Assistant, але не може працювати лише в браузері iPhone.

## Розгортання на Cloudflare

PWA та Worker мають бути розгорнуті **на одному Cloudflare-домені**: так браузер отримує захищену cookie-сесію без CORS і без cloud-токена у `localStorage`.

1. KV namespace `oukitel-home-sessions` уже прив'язаний у [wrangler.toml](wrangler.toml).
2. Один раз створіть серверний ключ шифрування: `wrangler secret put MONITOR_KEY`.
   Це має бути випадкове значення щонайменше 24 символи; не додавайте його до git.
3. Запустіть `wrangler deploy` — Worker сам віддає файли з `public/` і встановлює
   cron `*/5 * * * *`.
4. Відкрийте його URL, увійдіть у Wonderfree, оберіть станцію та за потреби
   увімкніть фоновий моніторинг.

Для локальної перевірки коду: `npm test` і `npm run check`.

## Безпека

Пароль використовується лише в POST `/api/login` через HTTPS та не пишеться у браузерне сховище. Звичайний Cloud token зберігається максимум 12 годин. Для явно ввімкненого фонового моніторингу зберігається лише AES-GCM-зашифрований службовий token; ключ є Cloudflare Worker secret `MONITOR_KEY`, а вибірки видаляються через 14 днів. Vendor `appSecret` у `worker.js` — не секрет користувача: це параметр мобільного застосунку, необхідний для відтворення протоколу входу.
